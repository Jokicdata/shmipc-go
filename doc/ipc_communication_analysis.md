#### 关键函数调用链

**客户端发送请求：**
```
mustWrite(stream, bodySize, b)
    └─ stream.BufferWriter().Reserve(likelySizes[bodySize])    // 在共享内存预留空间
    └─ json.NewEncoder(buf).Encode(request)                    // 直接写入共享内存（零拷贝）
    └─ stream.Flush(false)                                     // 发送数据
         └─ sendBuf.done(endStream)                            // 标记写入完成
         └─ session.sendQueue().put(queueElement{...})         // 写入队列元数据
         └─ session.wakeUpPeer()                               // 通过 UDS 发送轮询事件通知对端
              └─ eventConn.write(pollingEvent)                 // 写入轮询事件
```

**服务端接收请求：**
```
mustRead(stream, likelySizes[bodySize], b)
    └─ stream.BufferReader().ReadBytes(size)                   // 从共享内存读取数据
         └─ stream.readMore(minSize)                           // 等待数据到达
              └─ <-s.recvNotifyCh                              // 阻塞等待通知
         └─ sliceList.front().read(size)                       // 读取数据（零拷贝）
```

**服务端发送响应：**
```
mustWrite(stream, bodySize, b)
    └─ stream.BufferWriter().Reserve(likelySizes[bodySize])    // 在共享内存预留空间
    └─ json.NewEncoder(buf).Encode(request)                    // 直接写入共享内存
    └─ stream.Flush(false)                                     // 发送数据
```

**客户端接收响应：**
```
mustRead(stream, likelySizes[bodySize], b)
    └─ stream.BufferReader().ReadBytes(size)                   // 从共享内存读取数据
    └─ stream.ReleaseReadAndReuse()                            // 释放并复用缓冲区
```

#### 关键函数调用链

**客户端发送请求：**
```

    └─ json.NewEncoder(buf).Encode(request)                    // 序列化到用户态缓冲区

         └─ 系统调用 write()                                   // 用户态→内核态拷贝

```

```
    └─ conn.Read(buf[start:])                                  // 从内核读取（发生拷贝）
         └─ 系统调用 read()                                    // 内核态→用户态拷贝
```

**服务端发送响应：**
```
udsMustWrite(conn, writeBuffer)
    └─ json.NewEncoder(buf).Encode(request)                    // 序列化到用户态缓冲区
    └─ conn.Write(buf[wrote:])                                 // 写入内核（发生拷贝）
```

## 二、等待关系说明

### 2.1 Shmipc 方案等待关系

| 等待方 | 等待函数 | 被等待方 | 触发函数 | 说明 |
|--------|----------|----------|----------|------|
| 服务端 | `AcceptStream()` | 客户端 | `OpenStream()` | 服务端等待客户端创建 Stream |
| 服务端 | `BufferReader().ReadBytes()` | 客户端 | `Flush()` + `wakeUpPeer()` | 服务端等待客户端数据 |
| 客户端 | `BufferReader().ReadBytes()` | 服务端 | `Flush()` + `wakeUpPeer()` | 客户端等待服务端响应 |

**核心等待机制：**
1. 客户端 `Flush()` 将数据元信息写入共享内存队列
2. 客户端 `wakeUpPeer()` 通过 UDS 发送轮询事件通知对端
3. 对端收到事件后，从共享内存队列读取数据元信息
4. 对端直接从共享内存读取实际数据（零拷贝）

### 2.2 UDS 原生方案等待关系

| 等待方 | 等待函数 | 被等待方 | 触发函数 | 说明 |
|--------|----------|----------|----------|------|
| 服务端 | `conn.Read()` | 客户端 | `conn.Write()` | 服务端等待客户端数据 |
| 客户端 | `conn.Read()` | 服务端 | `conn.Write()` | 客户端等待服务端响应 |

**核心等待机制：**
1. 发送方 `conn.Write()` 将数据写入内核缓冲区
2. 接收方 `conn.Read()` 从内核缓冲区读取数据
3. 每次读写都需要在用户态和内核态之间进行数据拷贝

### 3.3 性能差异原因分析

#### Shmipc 优势

1. **零拷贝数据传输**
   - 数据直接写入/读取共享内存
   - 避免用户态与内核态之间的数据拷贝
   - 大包场景下性能提升显著

2. **批量 IO 处理**
   - 通过共享内存队列批量提交多个请求
   - 一次系统调用可处理多个请求
   - 减少系统调用开销

3. **缓冲区复用**
   - `ReleaseReadAndReuse()` 实现缓冲区复用
   - 减少内存分配和回收开销

#### UDS 原生方案特点

1. **每次读写都需要拷贝**
   - `Write()`: 用户态 → 内核态拷贝
   - `Read()`: 内核态 → 用户态拷贝
   - 大包场景下拷贝开销显著

2. **每次通信都需要系统调用**
   - 每次读写都涉及系统调用
   - 系统调用开销无法避免

### 3.4 适用场景

| 场景 | 推荐方案 | 原因 |
|------|----------|------|
| 小包通信（< 1KB） | UDS 或 Shmipc | 性能差异不大，UDS 更简单 |
| 大包通信（> 16KB） | Shmipc | 零拷贝优势明显 |
| 高吞吐量场景 | Shmipc | 批量 IO 减少系统调用 |
| 低延迟场景 | Shmipc | 减少拷贝和系统调用开销 |
| 跨平台需求 | UDS | Shmipc 仅支持 Linux |

## 四、核心组件说明

### 4.1 Session（会话）

Session 是 shmipc 的核心组件，负责管理进程间的通信会话。

- **客户端 Session**: 通过 `newSession(config, conn, true)` 创建
- **服务端 Session**: 通过 `Server(conn, config)` 创建

### 4.2 Stream（流）

Stream 是 shmipc 中的逻辑通信通道，类似于 HTTP/2 的 Stream 概念。

- **客户端**: 通过 `OpenStream()` 创建
- **服务端**: 通过 `AcceptStream()` 接受

### 4.3 共享内存队列（Queue）

队列用于存储数据元信息，包括：
- `seqID`: Stream ID
- `offsetInShmBuf`: 数据在共享内存中的偏移量
- `status`: 流状态

### 4.4 共享内存缓冲区（Buffer）

用于存储实际的通信数据，支持：
- `Reserve()`: 预留空间
- `ReadBytes()`: 读取数据（零拷贝）
- `ReleasePreviousRead()`: 释放已读缓冲区

## 五、总结

Shmipc 通过共享内存技术实现了进程间的零拷贝通信，相比传统的 UDS 方案：

1. **数据传输**: 共享内存零拷贝 vs 内核缓冲区拷贝
2. **同步机制**: UDS 仅传输通知事件 vs UDS 传输完整数据
3. **批量处理**: 支持批量 IO vs 每次单独处理
4. **性能表现**: 大包场景显著提升 vs 性能受限

这种设计使得 Shmipc 在 IO 密集型和大包通信场景下具有显著的性能优势。
