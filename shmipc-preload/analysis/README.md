# shmipc-preload 性能分析方案

## 一、问题现象

| 场景 | 小包时延 | 大包时延 | 带宽 |
|------|----------|----------|------|
| shmipc-preload | 提升 | 劣化 | 无明显差别 |

## 二、可能的原因分析

### 2.1 CGO 调用开销

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│                           CGO 调用开销分析                                        │
├─────────────────────────────────────────────────────────────────────────────────┤
│                                                                                 │
│  每次从 C 调用 Go 函数的开销：                                                    │
│                                                                                 │
│  ┌──────────────────────────────────────────────────────────────────────────┐  │
│  │  1. 栈切换         ~50-100ns                                              │  │
│  │  2. Go 运行时检查   ~20-50ns                                              │  │
│  │  3. 参数传递       ~10-30ns                                               │  │
│  │  4. 内存拷贝       取决于数据大小                                          │  │
│  │     - C.GoBytes() 会拷贝数据到 Go 内存                                    │  │
│  │     - 小包：拷贝开销小                                                    │  │
│  │     - 大包：拷贝开销显著                                                  │  │
│  └──────────────────────────────────────────────────────────────────────────┘  │
│                                                                                 │
│  关键问题：ShmipcWrite/ShmipcRead 中的 C.GoBytes()                              │
│                                                                                 │
│  // 当前实现                                                                    │
│  func ShmipcWrite(streamID C.int, data unsafe.Pointer, length C.long) C.long { │
│      buf := C.GoBytes(data, C.int(length))  // ← 这里会拷贝数据！              │
│      // ...                                                                    │
│  }                                                                             │
│                                                                                 │
│  拷贝开销 = 数据大小 × 内存带宽倒数                                              │
│  - 512B:    ~50ns (可忽略)                                                     │
│  - 64KB:    ~6μs                                                              │
│  - 512KB:   ~50μs (开始显著)                                                   │
│  - 1MB:     ~100μs (明显影响)                                                  │
│                                                                                 │
└─────────────────────────────────────────────────────────────────────────────────┘
```

## 四、优化建议

### 4.1 消除 CGO 拷贝

```go
// 优化方案：直接操作共享内存，避免 C.GoBytes 拷贝

// 方案 1：使用 unsafe.Slice (Go 1.17+)
func ShmipcWrite(streamID C.int, data unsafe.Pointer, length C.long) C.long {
    buf := unsafe.Slice((*byte)(data), length)  // 零拷贝！
    writer := stream.BufferWriter()
    n, _ := writer.WriteBytes(buf)
    stream.Flush(false)
    return C.long(n)
}

// 方案 2：使用共享内存直接写入
func ShmipcWrite(streamID C.int, data unsafe.Pointer, length C.long) C.long {
    writer := stream.BufferWriter()
    buf := writer.Malloc(int(length))  // 直接获取共享内存指针
    copy(buf, unsafe.Slice((*byte)(data), length))
    writer.Flush()
    return C.long(length)
}
```

### 4.3 批量处理

```c
// 优化方案：批量写入，减少 CGO 调用次数

// 在 C 层缓冲，批量调用 Go 函数
#define BATCH_SIZE 64

typedef struct {
    int stream_id;
    const void *data;
    size_t length;
} write_batch_t;

static write_batch_t g_write_batch[BATCH_SIZE];
static int g_batch_count = 0;

ssize_t send(int sockfd, const void *buf, size_t len, int flags) {
    // 累积到批次
    g_write_batch[g_batch_count].stream_id = info->stream_id;
    g_write_batch[g_batch_count].data = buf;
    g_write_batch[g_batch_count].length = len;
    g_batch_count++;
    
    // 批次满了才调用 Go
    if (g_batch_count >= BATCH_SIZE) {
        ShmipcWriteBatch(g_write_batch, g_batch_count);
        g_batch_count = 0;
    }
}
```
